# 00. 프로젝트 개요

## 한 줄 정의

> **AssetBox** — TA(Technical Artist) 반과 백엔드 반이 협업하는, 사내 교육·포트폴리오용 **3D 에셋 공유 포털**.

Sketchfab / BlenderKit 같은 상용 플랫폼을 참고하되, **사내 학습**과 **TA↔백엔드 협업 시뮬레이션**이 본질입니다.

---

## 왜 만드는가 (목적)

| # | 목적 | 성공 지표 |
|---|---|---|
| 1 | TA 반이 만든 3D 에셋을 한 곳에 모아 공유 | 배포 후 1주일 내 30개 이상 에셋 업로드 |
| 2 | 백엔드 반 8명이 실전형 협업 경험 (도메인 분할 + 머지) | 6/16까지 전 도메인 통합 + Critical 버그 0 |
| 3 | 요청 게시판으로 "원하는 에셋"을 TA에 의뢰하는 흐름 시뮬레이션 | 배포 후 요청→완료 한 사이클 이상 발생 |

**목적이 아닌 것**: 상용 출시, 외부 사용자 대상 서비스, 결제, SLA(서비스 수준 계약) 보장.

---

## 사용자(페르소나)

| 페르소나 | 역할(Role) | 핵심 기대 |
|---|---|---|
| TA 멤버 (창작자) | USER | 내가 만든 모델을 쉽게 올리고 자랑하고 싶다 / 요청을 받아서 작업하고 싶다 |
| TA + Unity + Unreal 멤버 (소비자) | USER | 다른 사람이 올린 에셋을 받아서 쓰고 싶다 / 부족한 게 있으면 요청하고 싶다 |
| 운영자 | ADMIN | 게시글·유저·요청·피드백 현황을 조회하고 서비스 상태를 모니터링하고 싶다 |
| 백엔드 PM | SUPER_ADMIN | 시스템 전체를 점검하고 권한 변경까지 가능 |

권한 위계: `SUPER_ADMIN > ADMIN > USER` (SecurityConfig RoleHierarchy에 반영됨)

## 핵심 도메인 (= 백엔드 반 8명이 나눠 가지는 영역)

```
user           회원, 인증(JWT), 프로필, 권한, teamId, OAuth(구글, 네이버), 이메일 화이트리스트
file           통합 파일 도메인: 에셋 / 썸네일 / 아바타 / 요청 참고이미지 저장·조회·메타·삭제
post(일반)      일반 게시글(에셋 공개), 좋아요, 조회수, 태그 연결
post(request)  요청 게시판(에셋 의뢰), 상태 흐름, TA 배정
comment        post / request 양쪽의 댓글·대댓글
category       카테고리 트리(3단계), 시드
tag            태그(M:N), 인기 태그 캐시
search         (= category 담당이 겸임) 태그/카테고리/제목 검색
message(DM)    1:1 DM, WebSocket 실시간, 인박스
infra          빌드/배포/CI/CD/모니터링/공통설정
```

상세 분담은 `01_planning/02_역할_분담표.md` 참조.

## 용어집 (혼동 방지)

| 용어 | 정의 |
|---|---|
| **에셋(Asset)** | 게시글에 첨부되는 3D 모델 파일 묶음 (fbx, blend, obj, glb, gltf, zip + 썸네일 png/jpg). |
| **포스트(Post)** | 에셋이 공개되는 일반 게시글. 카테고리·태그·파일을 가진다. |
| **리퀘스트(Request)** | "이런 에셋이 필요해요" 의뢰 게시글. 상태 5단계로 흐른다. |
| **카테고리 트리** | 대(1) → 중(2) → 소(3) 3단계 셀프 참조 트리. 한 번에 다 안 내려준다 (lazy). |
| **태그** | 자유 입력 키워드. 카테고리 오분류의 보완책. |
| **TA 배정** | 리퀘스트의 `assignee` 필드. TA(USER)가 `/assign`으로 본인을 담당자로 수락한다. |
| **teamId 스냅샷** | 게시글 작성 시점의 작성자 팀ID를 게시글에도 박아두는 패턴. 팀 이동 후에도 과거 글의 소속 추적 가능. |
| **소프트 딜리트(soft delete)** | `deleted = true` 플래그. 행을 지우지 않음. 댓글/포스트/리퀘스트에 적용. |

## 비기능 요구

| 항목 | 목표 |
|---|---|
| 응답시간 | 일반 API p95 < 400ms (개발 환경 기준) |
| 동시 사용자 | 50명 가정 (사내) |
| 가용성 | 영업시간 99% (학습용 서비스) |
| 보안 | JWT 인증, BCrypt 해시, CORS 화이트리스트, 어드민 엔드포인트 ROLE 분리 |
| 관측성 | Prometheus 메트릭 노출, 애플리케이션 로깅, 운영 지표, Feedback 기반 이슈 트리아주 |
| 배포 | Docker Compose (배포 단순화), MySQL + 백엔드 + 프론트 |

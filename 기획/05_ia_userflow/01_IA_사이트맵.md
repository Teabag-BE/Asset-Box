## 라우트 사이트맵 (프론트 기준)

```
/                       로그인 전 안내 / 로그인 후 최신·인기·카테고리 진입
├─ /login               로그인
├─ /signup              회원가입
├─ /profile/complete    첫 로그인 정보 보완 (major 누락 시 강제)
├─ /categories          카테고리 탐색 (대분류 그리드)
│  └─ /categories/:id   하위 분류 + 해당 카테고리 게시글
├─ /posts
│  ├─ /                 (= /search) 검색·필터 결과 리스트
│  ├─ /new              게시글 작성 (인증 필요)
│  └─ /:postId          상세 (썸네일·파일 목록·다운로드·좋아요·댓글)
├─ /requests            요청 게시판 목록 (status 필터)
│  ├─ /new              요청 작성
│  └─ /:requestId       요청 상세 (상태·배정·댓글·연결 결과물)
├─ /me                  내 프로필
│  ├─ /posts            내 게시글
│  ├─ /requests         내 요청
│  ├─ /likes            좋아요 누른 글
│  └─ /settings         프로필/아바타 수정
├─ /messages            DM 인박스
│  └─ /:partnerId       대화창 (WebSocket)
└─ /admin               (ADMIN 이상)
   ├─ /users            유저 목록 조회
   ├─ /posts            게시글 목록 조회
   ├─ /stats            운영 지표/통계 조회
   └─ /feedback         피드백 목록
```

> 본 프로젝트는 백엔드 중심이지만, **백엔드 API의 1차 클라이언트가 위 라우트들**이라는 것을 모든 도메인이 알고 있어야 합니다.

## 내비게이션 위계

| 레벨 | 무엇 | 항목 |
|---|---|---|
| 글로벌 헤더 | 항상 보이는 진입 | 로고 / 검색바(태그·키워드) / `/categories` / `/posts/new` / `/requests` / 알림 / 내 프로필 / DM 뱃지 |
| 컨텍스트 사이드바 | 페이지별 | 카테고리 트리(드릴다운), 정렬 옵션, 상태 필터(요청) |
| 푸터 | 부차 | 피드백 보내기, 도움말 |

---

## 정보 우선순위 (게시글 상세 페이지 기준)

1. 썸네일 (가장 큼)
2. 제목 / 작성자 / 카테고리 경로 / 태그
3. 다운로드 버튼 (파일 목록)
4. 본문 / 좋아요 / 조회수
5. 댓글
6. (작성자라면) 수정/삭제 버튼

## IA 설계 원칙

1. **요청 게시판은 일반 게시글과 라우트 분리.** 같은 게시글처럼 보이지만 라이프사이클이 달라(상태 5단계), 한 곳에 섞으면 사용자가 헷갈리고 코드도 섞임. → 백엔드도 `post` / `request` 도메인 분리와 일치.
2. **카테고리는 클릭으로 드릴다운.** 한 번에 트리 전체 노출 안 함. 백엔드 `roots` + `children` 두 API와 1:1.
3. **검색은 한 입구.** 글로벌 헤더의 검색바 + `/posts?...` 한 군데로 모음. (별도 `/search` 페이지 X)
4. **어드민은 분리 라우트.** `/admin` 하위는 모니터링·통계·피드백 확인 중심. 분쟁 처리, 게시글 강제 삭제, DM 강제 열람은 본 프로젝트 범위 밖.

# 12. 에러 코드 사전 (전 도메인 통합)

> ⚠️ **2026-05-22 회의 반영분과 충돌 시** [`02_엔드포인트_목록_상태코드분리_수정본.md`](./02_엔드포인트_목록_상태코드분리_수정본.md) **이 진실의 단일 원본.**
>
> 회의 결과 다음 변경이 적용됨:
> - **추가**: OAuth / 이메일 화이트리스트 / profileRequired / linkedRequestId 관련 코드
> - **제거 (MVP 범위 외)**: 어드민 강제 삭제, 분쟁 처리, 어드민 메시지 열람 관련 코드 (`POST_HARD_DELETE_FAILED` 등은 사용 안 함)
> - **변경**: Feedback `FEEDBACK_RATE_LIMITED` 는 익명 차단으로 사실상 불필요

> 비유: **사전.** 어디서나 `POST_NOT_FOUND` 라는 단어를 던지면 모든 8명이 같은 뜻으로 받는다. 사전이 흔들리면 코드와 프론트 사이 통역이 깨진다.

> 본 사전은 명세서(03~11)에 등장한 모든 `error.code` 값을 한 곳에 모은 단일 진실 소스입니다. 새 코드 추가 시 본 문서 갱신 후 사용.

## 0) 사용 규칙

1. **이 표에 없는 코드는 던지지 않는다.** 새 코드가 필요하면 본 문서에 먼저 추가 (PR 한 줄).
2. **메시지(한국어)는 가이드일 뿐.** 실제 응답 메시지는 사용 맥락에 맞게 더 상세히 써도 됨. 단 코드는 동일.
3. **검증 실패는 `VALIDATION_FAILED` 한 코드로 통일.** 필드별 상세는 `error.fields[]` 로 전달 (`01_API_표준.md` 1-3).
4. 한 엔드포인트가 같은 의미를 여러 코드로 던지지 않는다. (`POST_NOT_FOUND` 와 `POST_DOES_NOT_EXIST` 같은 중복 금지)

## 11) BusinessException 사용 패턴 (Real 표준)

코드와 메시지는 enum으로 묶어 관리하는 게 좋습니다.

```java
public enum ErrorCode {
    USER_NOT_FOUND(HttpStatus.NOT_FOUND, "해당 사용자를 찾을 수 없습니다."),
    USER_EMAIL_DUPLICATED(HttpStatus.CONFLICT, "이미 가입된 이메일입니다."),
    POST_NOT_FOUND(HttpStatus.NOT_FOUND, "해당 게시글을 찾을 수 없습니다."),
    // ...
    ;
    private final HttpStatus status;
    private final String defaultMessage;
    ErrorCode(HttpStatus status, String message) { this.status = status; this.defaultMessage = message; }
    public HttpStatus status() { return status; }
    public String defaultMessage() { return defaultMessage; }
}

public class BusinessException extends RuntimeException {
    private final ErrorCode code;
    public BusinessException(ErrorCode code) { this(code, code.defaultMessage()); }
    public BusinessException(ErrorCode code, String message) {
        super(message);
        this.code = code;
    }
    public ErrorCode code() { return code; }
}

// 사용
throw new BusinessException(ErrorCode.POST_NOT_FOUND);
throw new BusinessException(ErrorCode.POST_NOT_FOUND, "게시글 #42 가 존재하지 않습니다.");
```

`GlobalExceptionHandler` 에서는 `error.code = e.code().name()`, `error.message = e.getMessage()` 로 직렬화.

> 본 Real 표준은 Mock 의 단순 `BusinessException.notFound("...")` 와 다릅니다. ErrorCode enum 도입이 Real 의 핵심 개선점.

## 12) 신규 코드 추가 절차

1. 본 사전에 새 코드 + HTTP + 의미 추가 (한 줄)
2. 영향 받는 명세서(03~11) 의 해당 엔드포인트 에러 표에도 추가
3. `ErrorCode` enum 에 항목 추가
4. 동일 PR 안에 코드 변경 포함
5. 다른 도메인이 같은 의미로 던질 일이 있는지 확인 (중복 코드 방지)

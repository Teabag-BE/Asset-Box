## 3. 외부 컨트랙트

```java
public interface MessageService {
    /**
     * 시스템 또는 사용자가 메시지 송신. M1은 REST 저장/폴링, WS 푸시는 M2에서 추가.
     * @return 저장된 Message 의 응답 DTO
     */
    MessageResponse send(Long fromUserId, Long toUserId, String content);

    Page<MessageResponse> conversation(Long meId, Long partnerId, Pageable p);
    Page<ConversationSummary> inbox(Long meId, Pageable p);
    long unreadCount(Long meId);
    void markRead(Long meId, Long partnerId);    // 대화 진입 시 호출
}
```

### REST + WS 채널
- M1 REST: `04_api/02` 의 Message 섹션. 클라이언트는 inbox/unread 폴링으로 신규 메시지를 확인한다.
- M2 WS 구독:
  - `/user/queue/messages` — 본인 수신 메시지 푸시
  - `/user/queue/messages.unread` — 안 읽은 수 변동 시 푸시

### 발행 정책
- M2에서도 클라이언트는 **WS로 메시지 발행 X**. 모든 송신은 `POST /api/messages` 로.
- 발행 주체는 서버(컨트롤러)만. 이유: 일관된 검증·트랜잭션·로깅.

## 7. 충돌 방지 / 함정

| 함정 | 결과 | 회피 |
|---|---|---|
| WS에서 메시지 발행을 허용 | 검증 우회 | 무조건 REST 발행, WS는 구독만 |
| M1에 WS를 끼워 넣음 | 이슈 #12 범위 초과 | M1은 엔티티/Repository + REST 폴링 전제. WS는 M2 |
| inbox 쿼리가 N+1 | 응답 느려짐 | JPQL fetch join 또는 native subquery |
| 시스템 발신자 미존재 | 알림 깨짐 | 후속 SYSTEM USER 이슈에서 bootstrap 보장 |
| WebSocketConfig 를 단독으로 수정 | Infra와 충돌 | 변경 시 PR + Infra 리뷰 |
| StompJwtChannelInterceptor 를 User 모르게 수정 | 인증 깨짐 | 인증 로직은 User 협업 |

# 05. Slack 워크스페이스 · 채널 · 알림 설정

> 비유: **공사장의 무전기 채널.** 한 채널에서 모두 떠들면 정작 중요한 호출이 묻힌다. 채널별 역할을 미리 나눠두면 "어디서 말해야 하지?" 가 사라진다.
>
> 모르는 단어는 `[../00_overview/01_용어집.md](../00_overview/01_용어집.md)` 참고.

---

## 0. 왜 디스코드가 아니라 슬랙 인가

이번 프로젝트에서는 디스코드보다 **슬랙을 기본 협업 도구로 사용한다.**

디스코드는 실시간 음성 대화, 캐주얼한 소통, 커뮤니티 운영에는 매우 좋다.  

하지만 AssetBox 같은 팀 프로젝트에서는 단순히 “대화하는 것”보다 더 중요한 것이 있다.

바로 **업무 기록, 의사결정 추적, 알림 관리, GitHub 연동, 역할별 채널 분리**다.



즉, 디스코드는 “모여서 이야기하는 공간”에 가깝고,  

슬랙은 “일이 흘러가는 기록이 남는 협업 본부”에 가깝다.



팀 프로젝트에서는 매일 다음 내용을 짧게 공유해야 한다.



- 어제 무엇을 했는가

- 오늘 무엇을 할 것인가

- 막힌 것은 무엇인가



디스코드에서도 가능하지만, 대화가 빠르게 흘러가면 나중에 다시 찾기 어렵다.

슬랙에서는 `#assetbox-standup` 채널을 따로 만들고, 매일 같은 형식으로 남기면 된다.

```text

✅ 어제: User signup 검증 추가

🎯 오늘: JWT 발급 로직 + 단위 테스트

🚧 막힌 것: BCrypt 설정 위치가 헷갈림

이렇게 남기면 PM이 팀 전체 진행 상황을 빠르게 파악할 수 있고,  
나중에 회고나 발표 자료를 만들 때도 근거 자료로 사용할 수 있다.

---

### **0-1. 대화 아카이빙과 검색이 쉽다**

프로젝트 중에는 많은 결정이 생긴다.

예를 들면:

- API 응답 형식은 어떻게 할 것인가?
- 파일 업로드는 multipart로 할 것인가?
- 썸네일 URL은 응답에 포함할 것인가?
- SecurityConfig는 누가 수정하고 있는가?
- CI 실패 원인은 무엇이었는가?

이런 결정이 DM이나 흘러가는 채팅에만 남으면 나중에 다시 찾기 어렵다.

슬랙은 채널, 스레드, 검색 기능이 업무 기록에 최적화되어 있다.

예를 들어 나중에 다음처럼 찾을 수 있다.

```text
in:#assetbox-design thumbnail
in:#assetbox-arch SecurityConfig
from:jun JWT
has:link PR
```

즉, 슬랙은 단순 채팅방이 아니라  
**프로젝트의 기억 저장소** 역할을 한다.

---

### **0-3. 주제별 채널 분리가 명확하다**

한 채널에서 모든 이야기를 하면 중요한 내용이 쉽게 묻힌다.

예를 들어 같은 채팅방에서 아래 이야기가 동시에 오가면 혼란스럽다.

- 점심 메뉴
- PR 리뷰
- API 변경
- 에러 해결
- 회의 시간
- CI 실패
- 배포 문제

슬랙에서는 주제별로 채널을 나누어 역할을 명확히 할 수 있다.

```text
#assetbox-standup  → 매일 진행 상황
#assetbox-help     → 막혔을 때 도움 요청
#assetbox-arch     → 공유 자원 변경 선언
#assetbox-design   → 기획, API, ERD 변경 논의
#assetbox-pr       → GitHub PR 알림
#assetbox-ci       → GitHub Actions 알림
#assetbox-redteam  → 주간 리뷰 및 개선점 정리
```

이렇게 나누면 팀원이 “이 이야기를 어디에 써야 하지?”라고 고민할 필요가 줄어든다.

---

### **0-4. 스레드로 토론을 정리할 수 있다**

슬랙의 가장 큰 장점 중 하나는 **스레드 중심 대화**다.

본문에는 핵심만 짧게 적고, 자세한 논의는 스레드에서 이어갈 수 있다.

예시:

```text
[File] 요청 게시판에 썸네일 업로드 링크 섹션 추가 필요
```

그 아래 스레드에서:

```text
- thumbnailUrl 필드가 필요한가?
- 파일 업로드 API와 연결할 것인가?
- 게시글 생성 시 같이 받을 것인가?
- 별도 파일 업로드 후 URL만 저장할 것인가?
```

이렇게 하면 하나의 주제에 대한 논의가 흩어지지 않는다.

디스코드도 스레드가 있지만, 슬랙은 기본적으로 업무형 스레드 사용이 더 자연스럽다.

---

### **0-5. GitHub PR / Issue / CI 알림을 자동으로 받을 수 있다**

슬랙은 GitHub와 연동하기 좋다.

예를 들어 `#assetbox-pr`, `#assetbox-ci` 채널을 만들면 다음 알림을 자동으로 받을 수 있다.

- PR 생성
- PR 머지
- 리뷰 요청
- Issue 생성
- Issue 종료
- GitHub Actions 빌드 성공
- GitHub Actions 빌드 실패

예시:

```text
GitHub Bot:
Pull request opened: [User] Add JWT login flow
```

```text
GitHub Bot:
Workflow failed: backend-test.yml
```

이렇게 되면 팀원이 GitHub에 계속 들어가지 않아도 프로젝트 상태를 빠르게 알 수 있다.

특히 CI 실패 알림은 매우 중요하다.  
테스트가 깨졌는데 아무도 모르면 dev 브랜치 전체가 불안정해질 수 있기 때문이다.

---

### **0-6. 공유 자원 변경 선언에 좋다**

팀 프로젝트에서 가장 충돌이 많이 나는 파일은 보통 공유 자원이다.

예를 들면:

- `SecurityConfig`
- `build.gradle`
- `application.yml`
- 공통 응답 DTO
- ErrorCode
- BaseEntity
- 공통 예외 처리 클래스

이런 파일을 여러 명이 동시에 수정하면 충돌이 생기기 쉽다.

그래서 `#assetbox-arch` 채널에 먼저 선언한다.

```text
[SecurityConfig] 지금 OAuth 엔드포인트 추가하러 들어갑니다.
완료 예정: 30분 내.
영향: User + Infra 리뷰 필요할 듯.
```

이 선언은 일종의 **공사장 안전 깃발**이다.

“지금 이 구역 작업 중입니다.”라고 먼저 알리는 것이다.

이렇게 하면 같은 파일을 동시에 건드리는 일을 줄일 수 있다.

---

### **0-7. 30분 룰의 호출처로 쓰기 좋다**

프로젝트에서는 혼자 너무 오래 막히면 팀 전체 속도가 느려진다.

그래서 30분 룰을 둔다.

혼자 30분 이상 막히면 `#assetbox-help`에 도움 요청하기.

슬랙에서는 도움 요청을 다음처럼 남길 수 있다.

```text
[Post] 게시글 작성 시 multipart 파싱이 안 됩니다.
에러 메시지와 시도한 내용은 스레드에 남기겠습니다.
```

스레드에는 다음 내용을 적는다.

```text
- 에러 메시지
- 관련 코드
- 내가 시도한 방법
- 예상한 동작
- 실제 동작
```

이렇게 하면 도와주는 사람도 빠르게 상황을 이해할 수 있다.

중요한 것은 “모르겠습니다”가 아니라  
**“어디까지 시도했고, 어디서 막혔는지”를 공유하는 것**이다.

---

### **0-8. 일정과 미팅 안내에 적합하다**

슬랙은 reminder 기능을 통해 반복 알림을 설정할 수 있다.

예를 들어:

```text
/remind #assetbox-standup "오늘 스탠드업 작성해주세요 🌞" every weekday at 9:55am
```

```text
/remind #general "위클리 동기화 미팅 5분 후 시작" every Monday at 10:55am
```

```text
/remind #general "코드 리뷰 + Red Team Review 시작 (1h)" every Friday at 14:55
```

이렇게 하면 PM이 매번 직접 알리지 않아도 된다.

반복되는 운영은 자동화하고,  
PM은 더 중요한 조율과 판단에 집중할 수 있다.

---

### **0-9. 디스코드를 완전히 배제하는 것은 아니다**

디스코드가 나쁜 도구라는 뜻은 아니다.

디스코드는 다음 상황에서 오히려 더 좋다.

- 즉석 음성 대화
- 페어 프로그래밍
- 친목
- 캐주얼한 회의
- 화면 공유하며 같이 디버깅
- 스터디 커뮤니티 운영

다만 이번 프로젝트의 핵심은  
**기록이 남는 협업, GitHub 연동, 의사결정 추적, PM 운영 구조**다.

그래서 기본 협업 도구는 슬랙으로 두고,  
필요할 때만 디스코드나 슬랙 huddle을 보조적으로 사용할 수 있다.

---

### **0-10. 한 줄 결론**

디스코드는 **실시간으로 모여서 이야기하기 좋은 공간**이고,  
슬랙은 **프로젝트가 어떻게 진행되었는지 기록이 남는 업무 본부**다.

AssetBox 프로젝트에서는 단순 대화보다  
진행 상황, 결정사항, PR, CI, 도움 요청, 공유 자원 변경 기록이 중요하다.

그래서 이번 프로젝트의 기본 협업 도구는 슬랙으로 정한다.

## 1. 워크스페이스 생성 (PM이 1회)

1. [https://slack.com/get-started](https://slack.com/get-started) → "Create a new workspace"
2. 이메일 인증
3. 워크스페이스 이름: **AssetBox** (또는 팀 별칭)
4. URL: `assetbox-team.slack.com` 또는 비슷한 짧은 이름
5. 무료 플랜으로 충분 (90일 메시지 보관 제한이 있지만 학습 프로젝트엔 OK)
6. 8명 + PM 초대 (이메일 또는 초대 링크)

## 2. 채널 구조 (총 8~9개)

### 2-1) 기본 채널 (Slack 자동 생성)


| 채널         | 용도                           |
| ---------- | ---------------------------- |
| `#general` | 전체 공지. PM 만 글 권한 권장 (또는 공지만) |
| `#random`  | 잡담, 짤, 점심                    |


### 2-2) 본 프로젝트 채널 (PM이 직접 생성)


| 채널                  | 용도                                                         | 누가 자주 글         |
| ------------------- | ---------------------------------------------------------- | --------------- |
| `#assetbox-standup` | 매일 데일리 스탠드업 (어제/오늘/막힌 것)                                   | 전원 매일 1회        |
| `#assetbox-help`    | **막힐 때 호출** (30분 룰). 멘션 환영                                 | 막힌 사람 + 도와주는 사람 |
| `#assetbox-arch`    | 공유 자원(SecurityConfig, build.gradle, application.yml) 변경 선언 | 변경자             |
| `#assetbox-design`  | 기획·API·ERD 변경 토론. 회의록 링크                                   | PM + 도메인 담당자    |
| `#assetbox-pr`      | **GitHub PR 자동 알림** (앱 연동)                                 | 봇 (자동)          |
| `#assetbox-ci`      | **GitHub Actions 빌드/테스트 알림** (앱 연동)                        | 봇 (자동)          |
| `#assetbox-redteam` | 매주 금 Red Team Review 결과·이슈 정리                              | PM              |


> 위 채널 이름은 예시. 슬랙은 채널 이름 변경이 자유로워 나중에 바꿔도 OK.

### 2-3) 만들지 말 것 (혹은 매우 신중히)

- **도메인별 비공개 채널** (`#user-only`, `#post-only`) — 정보 분절. 다른 도메인 협업이 안 보임.
- **2명짜리 DM** 으로 중요한 결정 — 흔적이 안 남고 다른 사람이 못 봄. **공개 채널 스레드**가 원칙.

## 3. 채널별 사용 규칙 (각 채널에 핀 고정 권장)

### `#assetbox-standup` — 매일 10시까지

각자 3줄 (3분이면 끝):

```
✅ 어제: User signup 검증 추가
🎯 오늘: JWT 발급 로직 + 단위 테스트
🚧 막힌 것: BCrypt 설정 어디다 두지? (없으면 "없음")
```

PM 은 24시간 막힌 항목을 다음날 위클리 안건으로 올림.

### `#assetbox-help` — 30분 룰

- 혼자 30분 끙끙대지 말고 즉시 멘션
- 본문에 **에러 메시지 / 코드 / 시도한 것** 다 적기
- 형식: `[도메인] 한 줄 요약 — 상세는 스레드`
- 예: `[Post] 게시글 작성 시 multipart 파싱 안 됨 — 스레드에 코드`

### `#assetbox-arch` — 공유 자원 변경 선언

```
[SecurityConfig] 지금 OAuth 엔드포인트 추가하러 들어갑니다.
완료 예정: 30분 내.
영향: User + Infra 리뷰 필요할 듯.
```

다른 사람이 같은 파일을 동시에 안 건드리도록 **선점 깃발**.

### `#assetbox-design` — 기획·API 변경 토론

- 컨트랙트 변경(`04_api/`, `03_erd/`) 안건은 여기서 토론
- PR 머지 전 합의 시점
- 위클리 회의 안건도 미리 여기 던져두기

### `#assetbox-pr` / `#assetbox-ci` — 봇 전용

- 사람이 글 쓰지 말 것. 봇이 자동으로 PR / CI 결과를 푸시
- 봇이 푸시한 메시지에 **스레드로 토론** 가능

### `#assetbox-redteam` — 매주 금

- 그 주 Red Team Review 회의록 링크
- 발견된 이슈 GitHub 링크 (자동/수동)
- 다음 주 발표 순서

---

## 4. GitHub 연동 (PM이 1회 설정)

### 4-1) Slack GitHub 앱 설치

1. 슬랙 좌측 하단 "Apps" → "Add apps" → **"GitHub"** 검색 → Add
2. `/github subscribe assetbox-team/assetbox-backend` (레포 이름은 실제 것으로)
3. 채널 안에서 실행. 봇이 자동으로 해당 채널에 PR/Issue 알림 푸시

### 4-2) 채널별 구독 분리

`#assetbox-pr` 에서:

```
/github subscribe assetbox-team/assetbox-backend pulls,issues,releases
```

`#assetbox-ci` 에서:

```
/github subscribe assetbox-team/assetbox-backend deployments,statuses,workflows
```

> GitHub Actions 알림은 `workflows` 또는 `statuses` 가 핵심.

### 4-3) 알림 종류

- PR 열림 / 머지 / 닫힘
- PR 리뷰 요청 / 코멘트
- Issue 생성 / 클로즈
- CI 빌드 실패 / 성공 (실패만 알림 권장)

---

## 5. 알림 정책 (각자 본인 설정)

### 5-1) Working Hours

- 슬랙 프로필 → 알림 → **방해 금지 시간** 설정 (예: 23:00 ~ 08:00)
- 학습 프로젝트라 새벽 알림 받지 않는 게 정신 건강에 좋음

### 5-2) 채널별 알림


| 채널                  | 권장 알림                       |
| ------------------- | --------------------------- |
| `#assetbox-standup` | 매일 9:55 자동 알림 (슬랙 reminder) |
| `#assetbox-help`    | **모든 메시지** (도움 요청은 즉시)      |
| `#assetbox-arch`    | **모든 메시지** (충돌 방지)          |
| `#assetbox-pr`      | **본인 멘션만** (전체는 많음)         |
| `#assetbox-ci`      | **본인 멘션만** 또는 무음            |
| `#assetbox-design`  | **본인 멘션만**                  |
| `#assetbox-redteam` | **본인 멘션만**                  |


### 5-3) `@here` / `@channel` 룰

- `@here` = 채널 온라인인 사람만. 정말 필요한 때만 (긴급 도움)
- `@channel` = 채널 모두에게 알림. **PM 만 사용** (전체 공지 시)
- 멘션 남용하면 모두가 알림 꺼버림 → 정작 중요 호출 묻힘

## 10. 문제 해결


| 증상                 | 원인 / 해결                                                  |
| ------------------ | -------------------------------------------------------- |
| 멘션해도 답이 없음         | 알림 꺼두었거나 다른 채널 보고 있음. `#assetbox-help` 만이라도 모든 메시지 알림 권장 |
| 채널이 너무 많아서 헷갈림     | 자주 안 쓰는 채널은 "사이드바에서 숨기기" 로 정리. 채널 자체는 살려둠                |
| 봇 알림이 너무 많음        | 채널 구독 시 이벤트 목록 좁히기 (`pulls` 만 등)                         |
| 슬랙 90일 후 옛 메시지 사라짐 | 중요한 결정은 슬랙이 아니라 **기획 폴더 또는 GitHub Issue 에 박아둠**          |

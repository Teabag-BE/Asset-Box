# **1. 전체 목적 정리**

## **프로젝트 목적**

TA 팀이 만든 3D 모델링 에셋을 업로드하고, 백엔드/프론트 팀이 이를 관리·조회·다운로드할 수 있는 내부 포털을 만든다.

이 포털은 Sketchfab, BlenderKit, Poly Haven, FAB 같은 상용 플랫폼을 참고하되, 외부 판매 플랫폼을 완전히 구현하는 것이 목적은 아니다.

주요 목적은 다음과 같다.

```
1. TA 팀이 만든 3D 에셋을 정리해서 업로드한다.
2. 에셋별 썸네일, 설명, 파일 정보, 카테고리, 태그를 관리한다.
3. 다른 Unity / Unreal / 개발 반이 필요한 에셋을 찾아보고 다운로드할 수 있게 한다.
4. 에셋 요청 게시판을 통해 TA 팀과 다른 반 사이의 소통 창구를 만든다.
5. 나중에 Sketchfab 같은 외부 플랫폼에 에셋을 올려 판매하거나 공유하는 프로세스를 미리 경험한다.
```

# **2. TA 팀의 역할과 작업 흐름**

TA 팀은 단순히 모델링만 하는 팀이 아니라, **에셋이 실제 엔진에서 돌아갈 수 있도록 가공하는 역할**을 한다.

## **TA 팀 주요 업무**

```
모델링
텍스처링
최적화
스캔 데이터 / AI 데이터 가공
엔진에서 사용할 수 있는 형태로 변환
에셋 패키징
```

## **기본 작업 흐름**

```
Blender에서 모델링 제작
   ↓
텍스처링 / 머티리얼 작업
   ↓
High Poly → Low Poly 최적화
   ↓
FBX 등 엔진 호환 파일로 변환
   ↓
텍스처 파일 PNG/JPG 정리
   ↓
업로드용 패키지 구성
   ↓
포털에 업로드
   ↓
다른 반이 조회 / 다운로드 / 요청
```

여기서 중요한 포인트는:

TA 팀은 “예쁜 모델”만 만드는 게 아니라,

**엔진에서 실제로 사용할 수 있도록 최적화된 에셋을 만드는 과정**을 경험하는 것

# **3. 도메인 이해 정리**

## **참고 플랫폼**

다음 사이트들은 3D 에셋을 공유하거나 판매하거나 다운로드할 수 있는 플랫폼이다.

```
Sketchfab
BlenderKit
Poly Haven
FAB
ArtStation
AmbientCG
```

각 사이트는 조금씩 성격이 다르다.

```
Sketchfab
= 3D 모델 업로드, 360도 미리보기, 판매/공유 가능

BlenderKit
= Blender 안에서 바로 사용할 수 있는 모델/머티리얼/브러시 라이브러리

Poly Haven
= 무료 HDRI, 텍스처, 3D 모델 제공

FAB
= Unreal Marketplace, Sketchfab 등을 통합한 Epic Games 에셋 마켓플레이스 계열

ArtStation
= 포트폴리오 + 에셋 판매 성격

AmbientCG
= 무료 PBR 텍스처/머티리얼 중심
```

# **5. 파일 크기 관련**

에셋은 High Poly냐 Low Poly냐에 따라 파일 크기 차이가 크게 날 수 있다.
⇒ 아직 TA팀의 스케줄이 Low poly 과정만 진행해 확정 불가.
하지만 최대 17mb 정도면 인당 업로드 개수 제한을 두지 않아도 될 것 같다는 결론.

```
Low Poly 단순 모델: 수백 KB ~ 몇 MB
텍스처 포함 모델: 수 MB ~ 수십 MB
High Poly / 고해상도 텍스처 포함: 수십 MB 이상 가능
```

- 파일 업로드 정책 (추후 논의)

```
최대 업로드 용량
허용 확장자
파일 저장 위치
다운로드 방식
썸네일 생성 방식
파일 삭제 정책
스토리지 비용
```


## **EC2만 쓸 경우 ⇒ 위험**

EC2 서버 안에 파일을 직접 저장할 수는 있지만, 장기적으로는 위험할 수 있음

```
서버 용량 부족
배포 시 파일 관리 어려움
백업 어려움
서버 장애 시 파일 손실 위험
트래픽 증가 시 부담
```

보통 실무 구조

```
Spring Server
   ↓
파일 메타데이터는 DB 저장
   ↓
실제 파일은 S3 같은 Object Storage 저장
```

# **7. 저작권 이슈**

TA 팀의 경우 실제 이미지나 스캔 데이터, 외부 자료를 참고해서 모델링할 경우, 외부 공개나 판매에는 저작권 문제가 생길 수 있다.

현재 선생님 답변은:

```
외부 유출만 하지 않으면 내부 사용은 가능
```

그래서 포털은 일단 **회원가입/로그인 기반 내부 접근 서비스**로 만드는 게 좋을 것 같다는 결론.

## **정책 후보**

```
로그인한 사용자만 접근 가능
외부 공개 URL 차단
다운로드 권한 제한
업로드 시 저작권/출처 입력
상업적 사용 가능 여부 표시
내부 교육용 사용 여부 표시
```

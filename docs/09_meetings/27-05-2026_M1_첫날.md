### Post

1. post의 model쪽에서 팀 id는 주석상태로 만들어 놓기는 할까요?

-> 팀 id는 아얘 없애는 걸로.  
-> 에셋 제작자가 본인 에셋 다운로드 요청 시 승인해주는 방식으로 결정  
-> 팀 프로젝트때도 에셋 제작자가 본인의 팀 알아서 구분해 요청 받는 형식으로.  
-> 백엔드의 S3 가격 산정 방식에는 저장 비용 뿐만 아니라 다운로드 트래픽량도 포함. 요청 방식으로 하면 유저들의 무작위 다운로드 방어 가능.  
-> 

1. 태그 인기도 반영방식

-> M1에서 구현 해야할 문제는 아님 (가볍게 넣을 수 있는게 '해당 태그가 붙은 게시물 수' 기준으로)  
-> M2 구현 방식은 두 가지 (태그 클릭 수 or 그 태그가 붙은 게시글들의 조회수 합)  
-> M3 에서는 '반응성' 체크 기준으로 구현 가능 (인기 태그 = 게시글 수 + 조회수 + 좋아요 수를 섞은 점수 or 태그 클릭수, 검색어 로그, 다운로드 요청, 다운로드 승인 수, 최근 7일 트렌딩 태그 등 mix 가능)

1. admin post는 도메인 분리해야 할라나요?

-> 기능이 달라서 admin post 쪽은 따로 분리하는게 맞는듯.

### File

- 썸네일, 프로필은 URL로 넣기  
: Post 도메인의 thumnail_file_id 이름을 url로 바꾸기 + 연결관계 끊기  
  User 도메인의 avatar_path 이름을 profile_url 바꾸기  
- Request 도메인에 썸네일 URL 추가 (Nullable)  
- stored_path는 saved_url로 바꾸기  
- File 도메인의 resource_type 없애기  
  purpose를 domain_type으로 바꾸기  
  resource_id를 domain_id으로 바꾸기  
- deleted는 is_deleted? -> deleted at으로  
- 여러개의 파일의 순서를 기억하기위해 sort_order 필드 추가  
- Post에 폴리곤 수 정보가 있어야함.  
- 프로필 5mb  
- 썸네일 5mb  
파일 20mb  
- 파일 정책
